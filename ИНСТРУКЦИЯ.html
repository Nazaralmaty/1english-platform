01Три части и больше ничего

Сервера у платформы нет. Есть статические файлы, которые раздаёт GitHub, и база Supabase, куда браузер ходит напрямую.

Телефон ученикаHTML, CSS, JS. Работает и без сети
→
GitHub Pagesраздаёт файлы, бесплатно
→
Supabaseвход и база данных

Из этого следуют две вещи, которые определяют всё остальное. Первая: любой код, который вы видите в браузере, видит и ученик. Прятать в нём нечего. Вторая: раз защиты в коде быть не может, она целиком лежит в базе, в правилах доступа.

Что выкатывает новую версию

Каждый git push в ветку main. Через минуту-две ученики открывают обновлённую платформу, ничего не устанавливая.

Что стоит денег

Пока ничего. GitHub Pages бесплатен, Supabase на бесплатном тарифе, видео лежит на YouTube и раздаётся его серверами.

02Вход по номеру телефона

Ученик вводит номер и код из шести цифр. Первый раз код придумывает сам, дальше входит с ним же.

Почему без SMS

Телефонный вход в Supabase требует платного провайдера: около 30 ₸ за сообщение, и при регистрации, и при каждом входе. У 300 учеников с двумя входами в месяц это 18 000 ₸ в месяц на пустом месте. Поэтому номер превращается в технический адрес 77011234567@1eng.kz, письма туда физически не уходят, а настоящий номер лежит в базе отдельным полем. Когда подключите SMS-шлюз, переход пройдёт без потери аккаунтов.

Что происходит при первом входе

  1. Платформа пробует войти с этим номером и кодом.
  2. Не вышло — заводит аккаунт с тем же кодом в качестве пароля.
  3. Ошибка «уже зарегистрирован» означает, что человек ошибся кодом, а не что он новый.
  4. После входа создаётся строка в en_students и подтягивается всё, что уже есть в базе: имя, уровень, пройденные шаги.
Забытый код сбрасывается из дашборда. Кнопка «Сбросить код» в строке ученика: вводите новые шесть цифр и передаёте их ему. Прогресс остаётся на месте. Меняет код функция в базе, и только для аккаунта из en_admins.

03Что лежит в базе

Четыре таблицы. Открываются в Supabase → Table Editor.

ТаблицаЧто внутриКто пишет
en_students Одна строка на ученика: номер, имя, пол, уровень, язык интерфейса, тема, дата согласия на обработку данных Платформа при входе и при правке профиля
en_progress Одна строка на «урок + шаг». Шага три: read — урок, task — задание, words — словарь. У задания дополнительно счёт: сколько верных из скольких Платформа, когда ученик закончил шаг
en_admins Кто видит дашборд. Только id пользователя, номер сюда не пишется Вы, вручную
en_allowed Список допущенных номеров. Пустая таблица значит «пускаем всех» Вы, из дашборда
en_errors Падения у учеников: текст ошибки, файл, браузер. Последние двадцать видны в дашборде Платформа сама

Прогресс лежит по шагам, а не одной цифрой «60 %», нарочно: из шагов процент считается в любой момент, а из процента шаги обратно не достанешь. Дашборд поэтому умеет показать, кто застрял на конкретном уроке.

04Кто что видит

Правила доступа (RLS) живут в самой базе и работают до того, как запрос дойдёт до данных. Обойти их из браузера нельзя: браузер вообще не участвует в этой проверке.

КтоЧитаетПишетУдаляет
Учениктолько свои строкитолько своитолько свои
Аккаунт из en_adminsвсех учеников и весь прогресс только своитолько свои
Незалогиненныйничегоничегоничего
Вы в панели Supabaseвсёвсёвсё
Проверено на живой базе. Тестовый ученик видел ровно одну строку — свою. Запрос «покажи всех» вернул ему один результат вместо списка.

Дашборд не проверяет права в браузере. Он просто просит «дай всех учеников», и база сама решает, сколько строк отдать. Если аккаунта нет в en_admins, придёт одна строка, и дашборд честно скажет, что смотреть нечего.

05Два ключа: который можно показывать и который нельзя

можно anon

Лежит открыто в app/db.js, виден любому, кто откроет исходник страницы. Так и задумано: сам по себе он ничего не открывает, все запросы с ним проходят через правила доступа.

нельзя service_role

Игнорирует все правила и видит всю базу. В браузере его нет и быть не должно. Живёт только в панели Supabase. Если он куда-то утечёт, ключ нужно менять в тот же день.

Правило простое: в файлы платформы попадает только anon. Всё, что работает с service_role, запускается с вашего компьютера или с сервера, но не из браузера ученика.

06Что вы можете сделать сами

Всё ниже выполняется в Supabase → SQL Editor → New query → Run.

Дать себе дашборд

Сначала войдите в платформу своим номером, иначе аккаунта ещё нет.

select public.en_make_admin('+7 701 123 45 67');

Функция сама найдёт аккаунт по номеру и ответит словами, что получилось.

Пускать только своих учеников

Делается в дашборде, блок «Кто допущен»: поле для номера, кнопка «Добавить», крестик рядом с номером убирает его обратно. Пока список пуст, платформа принимает всех. Как только в нём появится первый номер, остальные увидят «Этого номера нет в списке группы» и внутрь не попадут, поэтому начинайте со своего номера.

То же самое запросом, если удобнее:

insert into public.en_allowed (phone, note)
values ('77011234567', 'Айсұлтан')
on conflict do nothing;

Выключить фильтр обратно: delete from public.en_allowed;

Сбросить забытый код

В дашборде, кнопка «Сбросить код» в строке ученика. Или запросом:

select public.en_reset_code('+7 701 123 45 67', '246810');

Посмотреть, кто сколько прошёл

select s.phone, s.name, s.level, count(p.*) as steps, max(p.updated_at) as last_seen
from public.en_students s
left join public.en_progress p on p.student_id = s.id
group by s.id
order by last_seen desc nulls last;

Удалить ученика

Authentication → Users, найти адрес вида 77011234567@1eng.kz, удалить. Профиль и прогресс уйдут следом сами. Сам ученик может стереть себя кнопкой «Удалить мои данные» в профиле.

Выгрузить базу в файл

На бесплатном тарифе автоматических бэкапов нет. Запускать раз в неделю из папки проекта:

EN_PHONE=77011234567 EN_CODE=123456 node backend/backup.mjs

Рядом с JSON появится .sql — им и восстанавливать: вставить в SQL Editor и выполнить. Через API восстановить нельзя, правила доступа не дают писать чужие строки, и это правильно. Обе папки в репозиторий не попадают.

Привязать видео к уроку

В файле app/course.js, таблица window.VIDEOS. Из ссылки youtu.be/3ZkombMruHM берётся хвост 3ZkombMruHM. Ключ — id урока: b Beginner, e Elementary, p Pre-Intermediate, i Intermediate, дальше номер от 1 до 14.

07Защита: три слоя и один открытый бок

1. Правила доступа в базе работает

Ученик читает и пишет только свои строки. Это единственная защита данных, и она не зависит от браузера. Работает уже сейчас.

2. Лимит попыток входа включите в панели

Код из шести цифр — миллион вариантов. Опасен не код, а возможность перебирать его быстро. Dashboard → Authentication → Rate Limits, поле Rate limit for sign ups and sign ins. Счёт идёт за 5 минут с одного IP, по умолчанию 30. Ставьте 20: живому человеку хватает трёх попыток, а перебор миллиона вариантов с одного адреса растянется больше чем на год.

Ниже 20 опускать не стоит: если класс сидит на одном школьном Wi-Fi, у всех учеников один и тот же адрес, и жёсткий лимит заблокирует их самих. И помните границу: лимит считается по IP, поэтому от перебора с сотни разных адресов он не спасает. От этого спасает список допущенных номеров.

3. Список допущенных номеров включается в дашборде

Держит подальше посторонних, пришедших по ссылке. Пока список пуст, заходят все; первый добавленный номер включает фильтр. Проверяет базу сама платформа при входе: чужой увидит отказ и внутрь не попадёт.

Открытый бок: правильные ответы видны в исходнике. Файл app/course.js уходит в браузер целиком, вместе с индексами верных ответов. Ученик, который умеет открыть исходник страницы, найдёт их. Пока учеников десяток и это свои — терпимо. Лечится переносом проверки в базу: вопросы отдаёт функция, ответ проверяет Postgres, в браузер приходит «верно / неверно» по одному заданию. Два дня работы.

Что защитой не является: пауза на минуту после пяти неверных кодов. Она останавливает соседа, взявшего чужой телефон, и ничего не значит для скрипта.

08Чего платформа сейчас не умеет

  • Показывать ученику, что он офлайн. Прогресс сохранится на телефоне и уедет в базу при следующем сохранении, но человек об этом не узнает.
  • Отправлять напоминания. Ни SMS, ни push.
  • Собирать статистику по конкретному заданию: видно, что задание пройдено на 5 из 6, но не видно, на каком именно вопросе ошиблись.
  • Работать с содержанием уроков на казахском. Интерфейс переключается, правила и переводы слов пока только русские.

Когда переходить на платный Supabase

Бесплатного тарифа хватает примерно до 50 активных учеников. Два повода перейти на Pro за $25 в месяц: проект перестанет засыпать после недели без запросов (первый ученик сейчас ждёт секунд тридцать) и появятся ежедневные бэкапы, которые не нужно помнить запускать.

10Если что-то сломалось

Сначала посмотрите дашборд

Внизу страницы блок «Падения у учеников»: платформа сама пишет туда каждую ошибку, которая случилась у ученика в браузере. Если там пусто, ищите причину в другом месте.

Ученик говорит, что прогресс не сохраняется

Откройте платформу, нажмите F12 → Console и найдите строки, начинающиеся с [db]. Там причина словами, а не кодом ошибки. Частые:

  • Could not find the table — схему не применили, запустите backend/supabase_min.sql заново.
  • Could not find the column — в базе нет колонки, которую ждёт код. Платформа отправит запрос без неё и сохранит остальное, но колонку стоит дописать тем же скриптом.
  • violates row-level security — номер не в списке en_allowed. Добавьте его в дашборде.

Дашборд показывает одного ученика вместо всех

Аккаунт не в en_admins. Выполните select public.en_make_admin(...) со своим номером и перезагрузите страницу.

Платформа не обновилась после правок

GitHub собирает страницу минуту-две. Если и после этого старая версия — откройте с добавкой ?v=2 в адресе: браузер держит файлы в кеше.

Проверить, что данные вообще доходят

Supabase → Table Editor → en_students. После входа ученика там появляется строка с его номером, после первого урока строка появляется в en_progress.
